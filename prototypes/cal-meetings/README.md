# Meetings design artifact

Run from the repository root:

```powershell
node prototypes/cal-meetings/render-components.cjs
node prototypes/cal-meetings/server.mjs
```

Open http://127.0.0.1:3147/. Use Booking, Meetings, Availability, Users and the theme switch. Users opens directly at http://127.0.0.1:3147/?view=users. The server binds only to loopback and serves an explicit file allowlist.

This is an interactive design artifact with labelled sample data. It creates no meetings, sends no messages, reads no credentials and makes no provider calls. Some configuration controls demonstrate their placement and describe the intended behavior rather than persist configuration.

The renderer imports the actual WDC `AdminShell`, `Panel`, `DemoNote`, `WdcMark` and installed Lucide icons. It substitutes inert routing, auth and optional tour adapters for rendering. Meetings is inserted into the rendered navigation for the proposed new page. It does not change production navigation or bypass authentication.

The preview serves the repository's actual `admin.css` and local Space Grotesk font files. This follows current `app/layout.tsx` and `globals.css`, where the body font token aliases Space Grotesk. The design documentation says Outfit; that existing discrepancy remains a separate decision, rather than changing production fonts as part of a preview repair.

`fidelity.css` handles meeting-specific geometry; the shared shell, control and panel rules remain in `admin.css`. `components.js` is generated by the renderer and must be rebuilt after shared components change.

For reproducible screenshots, import `capture.mjs` from the Browser skill's supported JavaScript session and call `captureDesign(browser, tab)`. It captures all four screens at 320, 390, 640, 768, 1024 and 1440px in both themes, rejects horizontal page overflow and restores the normal viewport. Use its `themes`, `widths` and `screens` options to run bounded batches; `restoreScreen` selects the screen left open. Screenshot fixtures contain no real client or account data.

Verified: booking through details/review, date/time selection, theme switching, 320px drawer and responsive geometry. Availability editing, provider data, calendar navigation across months and account controls are not production implementations.

The calendar title opens a custom month/year dialog; the year title opens a 12-year grid. Previous/next navigation and leap-year day counts are functional in the preview. Reminders under Availability demonstrates attendee and personal preferences, save/discard and explicit setup/delivery limits. The end-to-end contract is in `plans/cal-com-reminders-spec.md`; real reminder delivery remains an implementation/release check.

Phone layouts stack next-meeting actions and save controls, put weekly-hour controls beneath the weekday, and keep add-hours icons centered. The save bar stays in page flow on small screens so it cannot obscure the availability rows. Calendar entries use plain time/title text and a small status marker rather than tinted cards. The mobile calendar has one period selector and all four view controls; changing dates gives immediate visible feedback without sending a booking.


Users demonstrates Team, Invitations and Clients, invite/account dialogs, a read-only support banner, pinned tables, selection, reviewed bulk actions, pagination, page-size choices and CSV/JSON export scopes. These interactions update sample fixtures only. Production authorization, delivery, bulk results and export generation are being implemented separately.

The Users pagination markup is rendered from the actual shared `Pager`; row options use the existing three-dot menu styles. On phones the pinned person column is bounded so other columns can still be reached by horizontal scrolling. Full account details remain available from the row menu.
